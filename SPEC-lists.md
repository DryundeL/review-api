# Spec: персональные топы и подборки

Статус: черновик требований, реализация не начата.

## Цель

Добавить рядом с обзорами новую активность: пользователь создаёт шаблон
списка с фотографиями, другие пользователи составляют на его основе свои
топы и подборки и делятся результатами по прямым публичным ссылкам.
Ориентир механики — https://tiermaker.com/.

## Подтверждённые требования

- Используются существующие типы обзоров (`review_types`), отдельный
  справочник категорий для списков не создаётся.
- Автор шаблона задаёт тип, название, элементы и загружает их фотографии.
- У шаблона есть необязательное описание. В первой версии обложкой
  автоматически служит фотография первого элемента; отдельная загрузка
  обложки не предусмотрена.
- Элементы можно выбирать из существующего каталога произведений
  (название и постер подставляются автоматически) или добавлять вручную
  с названием и фотографией. Оба способа разрешено смешивать в одном шаблоне.
- Название и постер каталожного элемента сохраняются в шаблоне на момент
  добавления. Последующие изменения каталога не обновляют их автоматически.
  Автор шаблона может явно обновить данные элемента из каталога;
  ранее созданные результаты сохраняют свою исходную версию данных.
- Удаление произведения из каталога не удаляет его из существующих
  шаблонов и результатов: сохраняются название и изображение,
  а ссылка на удалённую карточку каталога не показывается.
- Каталожный элемент должен соответствовать типу шаблона: например,
  в шаблон типа «Игры» нельзя добавить фильм из каталога. Для ручных
  элементов соответствие теме остаётся на усмотрение автора.
- Одно произведение из каталога можно добавить в шаблон только один раз.
  Ручные элементы могут иметь одинаковые названия: они считаются разными
  элементами с собственными идентификаторами.
- Размер каждой загружаемой фотографии — не более 300 КБ.
- Допустимые форматы загружаемых фотографий: JPEG, PNG и WebP.
  GIF и SVG не допускаются. Формат проверяется по содержимому файла.
- Шаблон содержит не более 50 элементов; в формате тиров — не более 10 тиров.
- В формате тиров допускается от 1 до 10 групп. Для публикации обязательны
  непустые названия шаблона, элементов и тиров; описание необязательно.
- Максимальная длина названия шаблона и результата — 150 символов,
  необязательного описания — 2000 символов, названия элемента — 150 символов,
  названия тира — 30 символов. Длины считаются в символах Unicode,
  а не байтах; внешние пробелы удаляются перед проверкой.
- Пустой шаблон можно сохранить только как черновик. Для публикации
  нужен хотя бы один элемент; у каждого элемента должны быть название
  и изображение, в том числе у элементов из каталога.
- Формат выбирает автор шаблона: тиры, нумерованный топ или подборка
  без ранжирования. По умолчанию — тиры, как у TierMaker.
- После первой публикации тип произведения и формат шаблона менять нельзя,
  в том числе после возврата в черновик. Элементы, описание и настройки
  тиров остаются редактируемыми. Для другого типа или формата создаётся
  новый шаблон.
- Начальные тиры — S/A/B/C/D. Автор шаблона может менять их названия,
  цвета и количество. Пользователи составляют результаты с тирами,
  заданными автором шаблона.
- Порядок элементов внутри каждого тира значим и сохраняется.
  Пользователь может переставлять элементы между тирами и внутри тира.
- В подборке без ранжирования сохраняется заданный пользователем порядок
  отображения выбранных элементов, но номера мест не показываются.
  Порядок служит для оформления и не обозначает рейтинг.
- В нумерованном топе выбранные элементы занимают последовательные места
  от 1 до количества выбранных элементов, без пропусков и одинаковых мест.
- На основе шаблона другие пользователи составляют собственные результаты
  в выбранном автором формате.
- Результат составляется только из элементов исходного шаблона.
  Пользователь результата не может добавлять собственные элементы;
  он может оставить часть исходных элементов нераспределёнными.
- На странице чужого результата есть действие «Составить свой»:
  создаётся новый результат по исходному шаблону без копирования чужих
  оценок и расположения элементов. Создание требует авторизации.
  Действие доступно только для публичного исходного шаблона.
  Если шаблон удалён, снят с публикации или опубликован «Только по ссылке»,
  действие на странице результата недоступно. По шаблону «Только по ссылке»
  можно создать результат с собственной страницы шаблона.
- У результата есть собственное название и необязательное описание.
  Название по умолчанию берётся из шаблона; автор результата может его
  изменить, например на «Мой топ игр за 2026».
- Обложка результата формируется автоматически из изображения первого
  выбранного элемента: первое место нумерованного топа, первый элемент
  верхнего непустого тира или первый элемент подборки по порядку.
  Отдельная загрузка обложки результата не предусмотрена.
- Результат показывает исходный шаблон и его автора. Если шаблон доступен
  зрителю и опубликован публично, показывается ссылка на него.
  Если шаблон опубликован «Только по ссылке», ссылка на него в результате
  не показывается, даже если зрителю известен его адрес.
  Если шаблон удалён или недоступен
  зрителю, сохраняются исходное название и публичное имя автора,
  но ссылка на недоступный шаблон не показывается. Это не раскрывает
  содержимое черновика или приватные данные аккаунта.
- По шаблону «Только по ссылке» можно создать публичный результат,
  который отображается в общем разделе и профиле согласно обычным правилам.
  Видимость результата не меняет видимость исходного шаблона.
- Создание собственного списка требует авторизации.
- Гостям доступны общий раздел «Топы и подборки», поиск и фильтры,
  публичные шаблоны и результаты. Публикации «Только по ссылке» доступны
  гостям по прямому адресу. При попытке создать шаблон или собственный
  результат требуется вход.
- Опубликованные шаблоны и результаты показываются в отдельном разделе
  «Топы и подборки» и в профиле автора. В общую ленту обзоров
  эта активность на данном этапе не добавляется.
- В первой версии раздела «Топы и подборки» доступны поиск по названию
  и фильтры по существующему типу произведения и формату списка.
  Поиск и фильтры не раскрывают черновики и публикации «Только по ссылке».
- Раздел содержит две вкладки: «Шаблоны» и «Топы пользователей».
  По умолчанию открывается вкладка «Шаблоны».
- Автору доступен отдельный закрытый список «Мои» с фильтром по статусу,
  включая черновики и публикации «Только по ссылке». Этот список доступен
  только владельцу и не раскрывает такие объекты другим пользователям.
- Обе вкладки в первой версии сортируются по дате публикации: новые сверху.
  Сортировка по популярности в первую версию не входит.
- Для сортировки используется дата первой публикации. Редактирование
  и повторная публикация не меняют эту дату и не поднимают объект в разделе.
- Для опубликованных шаблонов и результатов доступен режим «Доступ только
  по ссылке»: просмотр без входа сохраняется, но объект не показывается
  в общем разделе и профиле автора. Это не приватный доступ: любой,
  получивший ссылку, может открыть объект.
- При первой публикации по умолчанию выбрана видимость «Публично»;
  режим «Только по ссылке» автор выбирает явно. До действия «Опубликовать»
  объект остаётся черновиком независимо от выбранной видимости.
- Автор может переключать опубликованный шаблон или результат между
  «Публично» и «Только по ссылке». Постоянная ссылка и дата первой
  публикации сохраняются; отображение в общем разделе и профиле
  меняется согласно выбранной видимости и ограничениям профиля.
- Приватность профиля не меняет видимость шаблонов и результатов:
  публичные публикации доступны в общем разделе и по прямой ссылке,
  публикации «Только по ссылке» — по прямой ссылке. Сам профиль и его
  списки сохраняют действующие ограничения доступа закрытого профиля.
  Черновики при любой настройке профиля доступны только автору.
- Один пользователь может создать несколько самостоятельных результатов
  по одному шаблону, например версии за разные годы. Каждый опубликованный
  результат имеет собственную постоянную ссылку; создание нового результата
  не заменяет предыдущий и не нарушает его ссылку.
- Для собственных шаблонов и результатов доступно действие «Создать копию».
  Копия создаётся как новый черновик, исходный объект и его ссылка
  сохраняются. Копия результата сохраняет выбранные элементы и расстановку;
  это отличается от действия «Составить свой» на чужом результате.
  Модерационные ограничения не должны обходиться через копирование.
- Копия собственного результата использует ту же сохранённую версию
  шаблона, даже если исходный шаблон изменён, удалён или снят автором
  с публикации. Если шаблон скрыт модератором, копирование результата
  блокируется.
- Автор может редактировать опубликованный результат с сохранением его
  постоянной ссылки. По ссылке открывается последняя сохранённая версия.
  Для сохранения отдельной версии пользователь создаёт новый результат.
- При редактировании опубликованного результата изменения становятся
  публичными только после явного нажатия «Сохранить». До этого зрители
  видят предыдущую сохранённую версию; промежуточная расстановка
  автоматически не публикуется.
- Неполный результат можно сохранять и публиковать: пользователь вправе
  оставить часть элементов шаблона нераспределёнными и оценить только
  знакомые ему элементы.
- Пустой результат можно сохранить как черновик, но нельзя опубликовать.
  Для публикации нужен хотя бы один выбранный элемент подборки,
  поставленный на место элемент топа или распределённый по тирам элемент.
- Во время составления черновик результата автоматически сохраняется
  с небольшой задержкой после изменений, чтобы расстановка не терялась
  при закрытии страницы. Конкретную задержку определить при реализации.
  Автосохранение черновика само по себе не публикует результат.
- Черновик шаблона также автоматически сохраняется с небольшой задержкой.
  Изменения опубликованного шаблона применяются только по кнопке
  «Сохранить»; до этого зрители видят предыдущую сохранённую версию.
  Сохранение обновлённого шаблона не меняет ранее созданные результаты.
- Шаблоны и результаты имеют черновик и отдельное действие «Опубликовать».
  До публикации они доступны только автору, после публикации — любому
  по прямой ссылке без авторизации.
- Автор может снять шаблон или результат с публикации, вернув его
  в черновик. Другим пользователям объект больше не доступен, в том числе
  по прямой ссылке. Повторная публикация восстанавливает доступ по той же
  ссылке. Снятие шаблона с публикации не скрывает и не изменяет ранее
  созданные чужие результаты.
- Автор может удалить собственный шаблон или результат. Удалённый объект
  недоступен по ссылке всем пользователям, включая автора; восстановление
  удалённых объектов в первой версии не предусмотрено. Удаление шаблона
  не удаляет результаты по нему и их сохранённые данные, кроме отдельно
  оговорённых модерационных ограничений. Для временного скрытия используется
  возврат в черновик.
- Существующие результаты сохраняют исходный состав и данные шаблона:
  изменение шаблона влияет только на новые результаты. Удаление шаблона
  не удаляет ранее созданные результаты и не нарушает их публичные ссылки.
  Способ сохранения исходных данных определить при проектировании хранения.
- Версия шаблона фиксируется в момент создания результата, в том числе
  черновика: состав элементов, их данные, формат и настройки тиров
  не меняются при последующем редактировании исходного шаблона.
- Удаление шаблона или снятие его с публикации не мешает автору уже
  созданного черновика завершить и опубликовать результат на основе
  сохранённой версии. Новые результаты по недоступному шаблону не создаются.
- Опубликованный результат доступен по постоянной прямой ссылке без
  авторизации. Ссылка не содержит учётных данных и не предоставляет
  право редактирования.
- Публичные ссылки шаблонов и результатов ведут на обычные веб-страницы,
  открывающиеся в браузере вне Telegram без входа, а не только на запуск
  Mini App. Вход требуется для создания и изменения, но не для просмотра.
  Страницы реализуются во фронтенде; API должен поддерживать гостевое чтение.
- В первой версии ссылки опубликованных шаблонов и результатов имеют
  превью для Telegram и других мессенджеров: название, обложка и публичное
  имя автора. Метаданные превью доступны без входа, в том числе для режима
  «Только по ссылке», с соблюдением текущей доступности объекта.
  Черновики, удалённые и скрытые модератором объекты не должны раскрывать
  содержимое через метаданные превью. Формирование метаданных выполняет
  фронтенд веб-страниц на основе доступных для гостя данных API;
  фактическое обновление превью зависит от кеширования мессенджера.

## Понятия и границы доступа

- **Шаблон** — исходный набор элементов с фотографиями, типом и форматом.
- **Результат** — собственный список пользователя на основе шаблона:
  распределение по тирам, порядок мест или выбранные элементы подборки.
- Автор результата определяется сервером по текущей авторизации,
  а не из переданного клиентом идентификатора.
- Изменение результата разрешается только его владельцу; публичный
  просмотр не должен раскрывать приватные данные аккаунта.

Создание и изменение шаблонов также предполагаются доступными только
авторизованному владельцу. Остальные правила жизненного цикла
нужно уточнить перед реализацией.

## Жалобы и модерация

- В первой версии пользователи могут жаловаться на шаблоны и результаты.
  Администратор может скрыть публикацию за нарушение.
- Отправка жалобы требует авторизации. От одного пользователя допускается
  не более одной активной жалобы на конкретный шаблон или результат.
- Для жалоб используется существующий справочник причин жалоб на обзоры;
  отдельный справочник для шаблонов и результатов не создаётся.
- Жалобы не скрывают публикацию автоматически независимо от их количества.
  В первой версии модерационное скрытие выполняет только администратор.
- Модерационное скрытие закрывает гостевой и публичный доступ, включая
  прямую ссылку. Автор не может обойти его обычной повторной публикацией.
- Если модератор скрывает шаблон, все результаты по нему также скрываются,
  в том числе по прямым ссылкам, а публикация уже начатых черновиков
  блокируется. Создание новых результатов по такому шаблону запрещено.
  Правило действует и для результатов на предыдущих версиях шаблона.
- Это исключение из сохранения доступности результатов при обычном
  удалении шаблона автором или снятии им шаблона с публикации.
- При восстановлении шаблона администратором снимается связанная с ним
  блокировка результатов и их публикации. Возвращается прежняя видимость,
  но независимо скрытые модератором, удалённые автором или снятые автором
  с публикации результаты не публикуются автоматически. Режим «Только
  по ссылке» сохраняется, черновики остаются черновиками.

## Архитектурные ограничения

- Сохранить текущую архитектуру модульного монолита на Go, Echo и PostgreSQL.
- Переиспользовать существующие авторизацию, справочник типов и механизм
  загрузки медиа через публичные контракты соответствующих модулей.
- Точное размещение функциональности в модулях и HTTP-контракт пока
  не определены; этот документ не утверждает новую границу модуля.
- Соблюдать принятые слои: domain, application, infrastructure, delivery/http.
  Пример принятого стиля проверки идентификатора:

  ```go
  if id == uuid.Nil {
      return contract.FieldError{Field: "id"}
  }
  ```
- Проверять принадлежность каждого элемента выбранному шаблону,
  допустимость размещения и отсутствие дубликатов.
- Ограничивать размеры запросов и загрузки изображений: не более 50 элементов
  на шаблон, не более 10 тиров, фотография не более 300 КБ.
  Остальные технические лимиты определить до реализации. Использовать существующие
  проверки медиа, не доверять имени файла и заявленному MIME-типу.
- Проверки доступа выполнять на сервере. Использовать параметризованные SQL;
  не раскрывать внутренние ошибки и секреты.

## Критерии готовности и проверки

- Можно создать шаблон с существующим типом и фотографиями элементов.
- При отсутствии явного выбора формата используется формат тиров.
- Авторизованный пользователь сохраняет собственный результат по шаблону.
- Гость открывает опубликованный результат по прямой ссылке без входа.
- Гость не может создавать или изменять списки; пользователь не может
  изменять чужой результат.
- Тесты покрывают форматы, авторизацию и владение, невалидный тип,
  чужие и повторяющиеся элементы, некорректные изображения и лимиты.
- Unit- и HTTP-тесты размещаются рядом с кодом (`*_test.go`);
  ограничения хранения проверяются интеграционными тестами PostgreSQL
  по существующему шаблону с `TEST_DATABASE_URL`.
- Команды проверки после реализации: `go test ./...`, `go vet ./...`,
  `go build ./cmd/...`. Изменение только этого документа не требует сборки.

## Границы текущего изменения

- Экспорт результата в картинку отложен; в первой версии делятся ссылками.
- Первая версия не включает комментарии и реакции на шаблоны и результаты.
  Её объём: создание, составление результатов, публикация и обмен ссылками.
- Сейчас фиксируются требования; код, БД и API не изменяются.
- Всегда: отделять подтверждённые требования от открытых вопросов,
  сохранять архитектуру и проверять доступ на сервере.
- Перед реализацией согласовать открытые продуктовые решения и контракт API.
- Не добавлять отдельные категории, новые зависимости, интеграции с лентой,
  геймификацией или уведомлениями без отдельного требования.
