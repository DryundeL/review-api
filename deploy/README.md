# Деплой review-api

## На сервере

В `/home/wapp/apps/review-api` находятся только:

- `.env` — настройки и секреты приложения, права `600`;
- `pull.sh` — перезапуск приложения, права `700`, владелец `wapp`.
- `storage/` — постоянное хранилище фотографий.

API, worker, bot и migrator получают весь `.env` через `env_file`.
В `environment` переопределяются только `DB_HOST=postgres`,
`REDIS_HOST=redis` для сети Docker и SHA версии релиза.
Шаблон — `deploy/env.example`. В `.env` можно оставить локальные
адреса `127.0.0.1`: Compose переопределяет их именами сервисов,
поскольку внутри API `127.0.0.1` указывает на сам API. Порты в `.env` задают также порты PostgreSQL и Redis.
Пустые `REDIS_USER` и `REDIS_PASSWORD` означают отсутствие авторизации.
Не пишите `null`: это строка. С паролем можно использовать пользователя
`default` или имя из букв, цифр, `_` и `-`; отдельное имя требует пароль.
`REDIS_DB` задаёт индекс логической базы Redis (по умолчанию `0`).

При перезапуске PostgreSQL не меняет пользователя, пароль и имя БД в уже
созданном volume. Менять эти поля надо согласованно с действующей БД.

Выполнять без `sudo`, от пользователя `wapp`:

```sh
cd /home/wapp/apps/review-api
sh pull.sh
```

Скрипт пересоздаёт API, worker и bot из уже доставленного образа, применяет
актуальный `.env` и ждёт готовности API. PostgreSQL и Redis не пересоздаются
принудительно, данные хранятся в Docker volumes. Скрипт не скачивает исходники
и не собирает образ на сервере. Любой другой пользователь, включая root,
получит отказ. Проверка пользователя не защищает от администратора, который
может изменить сам файл.

## Хранилище фотографий

API получает bind mount `storage/` в `/app/storage` с правом записи.
Остальная файловая система контейнера остаётся read-only; worker, bot и
migrator доступа к хранилищу не получают. Файлы не включаются в Git и
Docker build context.

`STORAGE_HOST_PATH` в серверном `.env` задавайте абсолютным путём:
`/home/wapp/apps/review-api/storage`. Это также значение по умолчанию, если
переменная отсутствует. Не используйте относительный путь на сервере:
Compose запускается из каталога конкретного релиза.

Перед первым деплоем с mount создайте папку и настройте владельца в
пространстве UID rootless Docker. Выполняйте от `wapp`, без sudo; вместо
`<SHA>` укажите тег уже загруженного образа:

```sh
mkdir -p /home/wapp/apps/review-api/storage
docker --context rootless run --rm --user 0:0 --network none \
  --mount type=bind,src=/home/wapp/apps/review-api/storage,dst=/storage \
  --entrypoint /bin/sh review-api:<SHA> \
  -c 'chown 10001:10001 /storage && chmod 755 /storage'
```

Compose намеренно не создаёт отсутствующую папку автоматически: запуск
завершится ошибкой вместо создания каталога с неподходящими правами.
Локально задайте `STORAGE_HOST_PATH=./storage`, создайте `storage/` в корне
репозитория и предоставьте UID контейнера `10001` право записи с учётом
режима Docker на вашей машине.

Фронтенд разворачивается отдельно. В его Compose подключите ту же папку
только для чтения (путь внутри контейнера согласуйте с его веб-сервером):

```yaml
services:
  frontend:
    volumes:
      - type: bind
        source: /home/wapp/apps/review-api/storage
        target: /app/storage
        read_only: true
        bind:
          create_host_path: false
```

Контейнеры должны работать на одном сервере. Для чтения фронтендом API
должен создавать публичные файлы с правами `0644`, вложенные каталоги —
`0755`. Mount сам по себе не настраивает HTTP-раздачу файлов и не добавляет
API загрузки. При прямой раздаче фронтендом файлы считаются публичными.

Резервируйте `storage/` отдельно от PostgreSQL, сохраняйте копии вне сервера
и проверяйте восстановление. Перезапуск и смена релиза не удаляют файлы.

## Автодеплой

Push в `main` запускает `.github/workflows/deploy.yml`: форматирование,
`go vet`, race-тесты, сборку Docker-образа на GitHub, доставку по SSH и вызов
`pull.sh` с SHA нового релиза. Pull request запускает только проверки и сборку.
Есть ручной запуск workflow для `main`.

GitHub Actions Secrets: `DEPLOY_SSH_KEY` — отдельный ключ `wapp`,
`DEPLOY_KNOWN_HOSTS` — проверенные SSH host keys сервера.
Токен бота и пароль БД остаются в серверном `.env`.
Доступ к изменению `main` и workflow означает доступ к деплою.

Служебные файлы находятся в `/home/wapp/.local/share/review-api`:

- `releases/<SHA>` — Compose и скрипт релиза;
- `current` — ссылка на последний успешно запущенный релиз;
- `incoming` — временные архивы доставки;
- `deploy.lock` — общая блокировка ручного запуска и автодеплоя.

Деплои последовательные. При неготовности API скрипт завершается ошибкой,
worker и bot остаются остановленными; ссылка `current` не меняется. Это не
zero-downtime деплой. Проверка worker и bot подтверждает запуск процесса,
успешность обработки outbox и `/start` проверяйте в логах.

## Проверка и откат

```sh
curl --fail http://127.0.0.1:8080/readyz
docker --context rootless logs --tail=100 review-api-worker-1
```

Откат на сохранённый совместимый образ:

```sh
sh /home/wapp/apps/review-api/pull.sh <PREVIOUS_SHA>
```

Схема БД автоматически назад не откатывается. Перед несовместимыми
миграциями нужен отдельный план восстановления. Сохраняйте предыдущие образы.

Резервная копия БД от `wapp`:

```sh
umask 077
docker --context rootless exec review-api-postgres-1 pg_dump -U review -d review -Fc > "$HOME/backups/review-$(date +%Y%m%d-%H%M%S).dump"
```

Копируйте резервные копии за пределы сервера и проверяйте восстановление.
Не используйте `docker compose down -v`: это удалит данные.
Изменение `DB_PASSWORD` в `.env` не меняет пароль уже созданной БД.

## Доступ без домена

API слушает `127.0.0.1:8080`. Postgres опубликован на `0.0.0.0:5432`. На компьютере API по-прежнему через туннель:

```sh
ssh -N -L 8080:127.0.0.1:8080 -i ~/.ssh/my_server wapp@194.146.223.221
```

Проверка API: `curl --fail http://localhost:8080/readyz`.
Клиент БД с локальной машины: хост `194.146.223.221`, порт `5432`, база и пользователь `review`, пароль `DB_PASSWORD` из серверного `.env`, `sslmode=disable`.
Для будущего домена подготовлен `deploy/nginx.conf`; требуется HTTPS.

## Локальная сборка

Из клона репозитория на Linux: создайте `.env` по `deploy/env.example`,
заполните секреты и выполните `sh deploy/deploy.sh`.
Production использует rootless Docker пользователя `wapp` с автозапуском
user service и `loginctl enable-linger wapp`.
