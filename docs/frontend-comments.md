# Комментарии и уведомления: контракт для фронтенда

Все пути начинаются с `/v1`. Для создания нужен Bearer-токен. Читать можно без
авторизации; переданный токен проверяется. Обсуждение доступно только у
опубликованного отзыва, включая запросы его автора.

## Создание

`POST /reviews/:reviewId/comments`

```json
{ "body": "Мой комментарий", "parentId": null }
```

Для ответа передать в `parentId` UUID комментария того же отзыва. Глубина
ответов API не ограничивается. Автор берётся из токена. Текст после удаления
внешних пробелов — 1–2000 Unicode-символов. Максимальный JSON — 32 КиБ.

Успех — HTTP 201 с одним комментарием:

```json
{
  "id": "53f5e1ab-3766-426d-9ef7-7ce5b8edab83",
  "reviewId": "0ec1b87e-cc81-47fa-8787-5d6f5e11a191",
  "parentId": null,
  "author": {
    "id": "71171010-28ed-47ad-853c-109a7c91f90c",
    "username": "reader",
    "photoUrl": "",
    "isFollowing": false,
    "avatarFrame": "",
    "backdrop": ""
  },
  "body": "Мой комментарий",
  "createdAt": "2026-11-14T05:00:00.123456Z",
  "hasReplies": false
}
```

Заполняются публичные `author.id`, `username`, `photoUrl`; остальные поля общей
структуры автора имеют значения по умолчанию. `body` — обычный текст: выводить
через текстовый узел React, без `dangerouslySetInnerHTML`. HTML-разметка блоков
обзора не распространяется на комментарии.

## Ленивая загрузка

- Корни: `GET /reviews/:reviewId/comments?limit=20`.
- Прямые ответы: `GET /reviews/:reviewId/comments?parentId=:commentId&limit=20`.
- Продолжение: тот же запрос с URL-encoded `cursor`, полученным в `nextCursor`.

```json
{ "items": [], "nextCursor": null }
```

`items` содержит только один уровень дерева, в порядке от старых к новым.
При `hasReplies=true` показывать раскрытие ответов. Потомки не включаются в
страницу автоматически. По умолчанию 20 записей, допустимый `limit` — 1–50.
`nextCursor=null` означает конец списка на момент запроса.

Хранить отдельный список, курсор и состояние загрузки для каждой пары
`(reviewId, parentId)`, включая корни с `parentId=null`. Курсоры нельзя переносить
между ветками или отзывами либо разбирать на клиенте. Объединять страницы по
`id`. После создания ответа обновлять его список и `hasReplies` родителя.

## Уведомления

- `comment`: автору отзыва о новом корневом комментарии.
- `comment_reply`: автору непосредственного родителя о новом ответе.

Ответы не рассылаются всем предкам. Уведомления на собственные действия
отсутствуют. Обработка асинхронная через worker; повтор outbox-события
не дублирует inbox и не повторяет отправку Telegram.

`GET /notification-settings` возвращает два новых типа, включённых по умолчанию.
Их можно независимо переключать через `PATCH /notification-settings`:

```json
{
  "items": [
    { "name": "comment", "enabled": false },
    { "name": "comment_reply", "enabled": true }
  ]
}
```

Отключение типа выключает inbox и Telegram; `allowNotifications=false` в общих
настройках выключает только Telegram. Полный текст комментария не отправляется
в Telegram. Ошибки Telegram не отменяют inbox; повторной доставки Telegram нет.

В `GET /notifications` новые уведомления содержат `reviewId`, `commentId` и
nullable `parentCommentId`. При открытии загрузить корни, если
`parentCommentId=null`, либо прямые ответы `parentCommentId`, затем выделить
`commentId`. Он может находиться на последующих страницах. При 404 показать
недоступность обсуждения.

## Ошибки и запуск

- 400 — некорректный JSON или превышение размера тела запроса.
- 401 — нет авторизации для создания либо токен недействителен.
- 404 — нет опубликованного отзыва или родитель отсутствует в этом отзыве.
- 422 `VALIDATION_ERROR` — неверные UUID, текст, `limit`, `parentId`, `cursor`;
  поле указано в `error.details.field`.

Перед обновлением API/worker применить миграции `00030_review_comments.sql` и
`00031_comment_notifications.sql`: `go run ./cmd/migrator -command=up`.
Откат миграций удаляет комментарии и уведомления этих двух типов.
