# Топы и подборки: контракт для фронтенда

Модуль `lists` состоит из двух сущностей:

- **Шаблон** (`list-templates`) — набор элементов: произведения из каталога или свои картинки.
  Автор шаблона задаёт формат и, для тир-листа, тиры.
- **Результат** (`list-results`) — раскладка элементов чужого или своего шаблона:
  тир-лист, топ или подборка. Результат строится на неизменяемом снимке шаблона.
  Позднейшие правки шаблона его не меняют.

Все маршруты начинаются с `/v1`. Тело запроса и ответа — JSON, даты в ISO 8601 (UTC).

- **Запись** требует `Authorization: Bearer …`. Без него ответ 401.
- **Чтение** работает и без входа. Если вход есть, автор объекта получает дополнительные поля.

Связанные документы: загрузка картинок — [frontend-media.md](frontend-media.md),
причины жалоб — `GET /v1/report-reasons`, типы — `GET /v1/review-types`.

## 1. Форматы

| `format` | Что это | Тиры шаблона | Элемент результата (`entries[]`) |
|---|---|---|---|
| `tiers` (по умолчанию) | тир-лист | 1–10 штук | `tierId` обязателен, `position` — порядок внутри тира |
| `ranked` | топ | нет (`tiers: []`) | без `tierId`, `position` — место |
| `collection` | подборка | нет (`tiers: []`) | без `tierId`, `position` — порядок |

Правила `position`:

- Позиции начинаются с 1.
- В каждой группе (тир или весь список) они идут строго `1, 2, …, n`, без пропусков и повторов.
- Раскладывать все элементы не обязательно: неразложенные просто не передаются в `entries`.

Новый тир-лист получает тиры по умолчанию:

| Тир | Цвет |
|---|---|
| S | `#ff7f7f` |
| A | `#ffbf7f` |
| B | `#ffdf7f` |
| C | `#ffff7f` |
| D | `#bfff7f` |

## 2. Типы (TypeScript)

```ts
type Format = "tiers" | "ranked" | "collection";
type Status = "draft" | "published";
type Visibility = "public" | "unlisted";

interface Author { id: string; username: string; photoUrl?: string }

interface Tier { id: string; name: string; color: string } // color: "#rrggbb"

interface Item {
  id: string;
  title: string;
  mediaObjectId?: string; // элемент из каталога
  imageUrl?: string;
  imageId?: string;       // только автору шаблона и только для его загрузки
}

// Поля, которые получает только автор объекта
interface OwnerFields {
  revision?: number;
  status?: Status;
  visibility?: Visibility;
  moderation?: "hidden"; // объект (или шаблон результата) скрыт модератором
  createdAt?: string;
  updatedAt?: string;
}

interface Template extends OwnerFields {
  id: string;
  typeCode: string;
  format: Format;
  title: string;
  description: string;
  coverUrl?: string;
  author: Author;
  firstPublishedAt?: string;
  tiers: Tier[];          // пусто для ranked и collection
  items: Item[];
  canCreateResult: boolean;
}

interface Entry { itemId: string; tierId?: string; position: number }

interface Result extends OwnerFields {
  id: string;
  typeCode: string;
  format: Format;
  title: string;
  description: string;
  coverUrl?: string;
  author: Author;
  firstPublishedAt?: string;
  template: { id?: string; title: string; author?: Author };
  canCreateOwn: boolean;
  tiers: Tier[];          // из снимка шаблона
  items: Item[];          // из снимка шаблона
  entries: Entry[];       // в каноническом порядке
}

interface Card extends Pick<OwnerFields, "status" | "visibility" | "moderation" | "updatedAt"> {
  id: string;
  title: string;
  typeCode: string;
  format: Format;
  coverUrl?: string;
  author: Author;
  firstPublishedAt?: string;
  templateTitle?: string; // только у результатов
}

interface Page { items: Card[]; nextCursor?: string }

interface ApiError {
  error: { code: string; message: string; details?: { field: string; reason: string; index?: number } };
}
```

### Что видит гость

Гость и любой пользователь, кроме автора, никогда не получают:

- `revision`, `status`, `visibility`, `moderation`, `createdAt`, `updatedAt`;
- `imageId`.

Черновики и скрытые объекты для них — 404. Поэтому отличать по ответу «нет такого» от «закрыто» не нужно, и это невозможно.

## 3. Экраны и сценарии

### 3.1 Разделы и списки

| Маршрут | Экран | Что в нём |
|---|---|---|
| `GET /list-templates` | вкладка «Шаблоны» | опубликованные публичные шаблоны |
| `GET /list-results` | вкладка «Топы пользователей» | опубликованные публичные результаты |
| `GET /profiles/:userId/list-templates` | профиль | то же, но одного автора |
| `GET /profiles/:userId/list-results` | профиль | то же, но одного автора |
| `GET /profile/list-templates` | «Мои шаблоны» | всё своё, кроме удалённого |
| `GET /profile/list-results` | «Мои топы» | всё своё, кроме удалённого |

Параметры разделов и профиля:

| Параметр | Значение |
|---|---|
| `q` | поиск подстроки в названии без учёта регистра, до 100 символов |
| `type` | код типа (`manga`, …) |
| `format` | `tiers`, `ranked` или `collection` |
| `limit` | 1–50, по умолчанию 20 |
| `cursor` | значение `nextCursor` из предыдущего ответа |

Параметры «Моих»:

| Параметр | Значение |
|---|---|
| `status` | пусто — все; `draft`; `published` (только публичные); `unlisted`; `hidden` (скрытые модератором) |
| `limit`, `cursor` | как выше |

Как устроены списки:

- **Сортировка.** Раздел и профиль сортируются по дате первой публикации, новые первыми.
  Снятие с публикации и повторная публикация её не сбрасывают. «Мои» сортируются
  по последнему изменению.
- **Курсор.** Курсор привязан к вкладке и фильтру `status`. При смене `q`, `type`, `format`
  или `status` начинайте с первой страницы без `cursor`. Если `nextCursor` нет, это последняя страница.
- **Закрытый профиль.** Если профиль закрыт, а зритель не подписчик и не владелец,
  профильные списки дают 404. В разделах публикации такого автора видны.
- **Скрытые модератором** объекты в «Моих» видны только при фильтре `hidden`. В карточке
  у них `moderation: "hidden"`. Результат попадает туда и тогда, когда скрыт его шаблон.
- **Видимость `unlisted`.** Такой объект не попадает в разделы и профиль, но открывается
  по прямой ссылке.

### 3.2 Страница шаблона

`GET /list-templates/:id` возвращает `Template`.

- **«Составить свой топ»** показывайте при `canCreateResult: true`. Гостю сначала предложите войти.
  Нажатие — `POST /list-templates/:id/results` → 201 `Result` (черновик), затем переход в редактор результата.
- **Автор** получает свои поля. Если `status: "draft"`, страница открывается только у него.
- **`moderation: "hidden"`**: покажите автору плашку «Скрыто модератором». Остальные получают 404.

### 3.3 Страница результата

`GET /list-results/:id` возвращает `Result`.

- **Отрисовка.** Тиры и элементы берите из `tiers` и `items` ответа: это снимок шаблона.
  Раскладка — `entries`; элемент находите по `itemId`.
- **Ссылка на шаблон и «Составить свой»** показывайте только при `canCreateOwn: true`.
  Тогда же приходит `template.id`, и «Составить свой» — это `POST /list-templates/:template.id/results`.
  Если `canCreateOwn: false`, у шаблона показывайте только название и автора, без ссылки.
- **Без ссылки.** Если шаблон удалён, снят с публикации или открывается только по ссылке,
  результат по-прежнему открывается, но без ссылки на шаблон.

### 3.4 Редактор шаблона

1. **Создание.** `POST /list-templates`:

   ```json
   { "typeCode": "manga", "format": "ranked", "title": "Лучший сэйнэн" }
   ```

   `format` и `title` необязательны. Без `format` создаётся `tiers` с тирами по умолчанию.
   Ответ 201 — `Template` с `revision: 1` и `status: "draft"`.
2. **Картинки своих элементов** загружайте через `POST /media/images`, потом передавайте `imageId`.
   Загрузка, которая за 24 часа ни к чему не привязана, удаляется.
3. **Сохранение.** `PUT /list-templates/:id` — **полная замена** содержимого:

   ```json
   {
     "revision": 1,
     "title": "Лучший сэйнэн",
     "description": "",
     "typeCode": "manga",
     "format": "tiers",
     "tiers": [
       { "id": "…", "name": "S", "color": "#ff7f7f" },
       { "name": "Новый тир", "color": "#7fbfff" }
     ],
     "items": [
       { "mediaObjectId": "…" },
       { "title": "Своя картинка", "imageId": "…" },
       { "id": "…", "title": "Переименованный элемент" }
     ]
   }
   ```

   Ответ 200 — `Template` с новой `revision`.
4. **Публикация.** `POST /list-templates/:id/publish`:

   ```json
   { "revision": 2, "visibility": "public" }
   ```

   Ответ 200 — `Template`.

#### Правила `PUT` для тиров

- Существующий тир передаётся со своим `id`, новый — без `id` (сервер выдаст id).
- Тиры, которых нет в запросе, удаляются. Порядок в массиве — порядок сверху вниз.
- Для `ranked` и `collection` передавайте `tiers: []`, иначе 422 `tiers/invalid`.
- Для `tiers` нужно от 1 до 10 тиров. `name` — до 30 символов, `color` — строго `#RRGGBB`.

#### Правила `PUT` для элементов

- **Новый элемент из каталога**: `mediaObjectId` без `id`.
  - Название и постер сервер берёт из каталога. Свой `title` заменяет название, `imageId` — постер.
  - Произведение должно быть того же типа, что шаблон (`type_mismatch`).
  - Одно произведение нельзя добавить дважды (`duplicate`).
- **Новый свой элемент**: `title` и `imageId`, без `id`.
- **Существующий элемент**: со своим `id`.
  - **`title` передавайте всегда**: он заменяет текущее название.
  - Без `imageId` текущая картинка сохраняется.
  - `mediaObjectId` у элемента менять нельзя (`immutable`).
- Неизвестный `id` тира или элемента даёт 422 `invalid`.
- Элементы, которых нет в запросе, удаляются. Порядок в массиве — порядок элементов.
  Первый элемент становится обложкой шаблона.
- До 50 элементов, название элемента — до 150 символов.

#### Правила `PUT` для полей шаблона

- `title` — до 150 символов, `description` — до 2000.
- `typeCode` и `format` необязательны: без них остаются прежние. После первой публикации
  менять их нельзя (`immutable`).
- **Опубликованный шаблон** при сохранении должен оставаться пригодным к публикации,
  потому что правка сразу видна всем.

#### Публикация и другие действия

**Условия публикации:**

- есть название;
- есть хотя бы один элемент;
- у каждого элемента есть название (`items.title`) и картинка (`items.image`);
- у каждого тира есть название.

**Другие действия:**

| Действие | Запрос | Ответ |
|---|---|---|
| Снять с публикации | `POST /list-templates/:id/unpublish` | 200 `Template` |
| Сменить видимость (только опубликованного) | `PATCH /list-templates/:id/visibility` `{ "visibility": "unlisted" }` | 200; у черновика — 409 |
| Обновить элемент из каталога | `POST /list-templates/:id/items/:itemId/refresh-from-catalog` `{ "revision": 3 }` | 200, `revision` растёт; свой элемент или произведение удалено из каталога — 409 |
| Копировать (только свой) | `POST /list-templates/:id/copy` | 201, новый черновик |
| Удалить | `DELETE /list-templates/:id` | 204 |

- После удаления шаблон даёт 404 всем, включая автора. Опубликованные результаты по нему остаются.
- Результаты, созданные раньше, не меняются ни после правки, ни после обновления элемента из каталога.

### 3.5 Редактор результата

1. **Создание.** `POST /list-templates/:templateId/results` → 201 `Result`, черновик.
   - Работает для любого опубликованного и не скрытого шаблона, который открывается
     у пользователя, в том числе `unlisted`.
   - Свой черновой шаблон — 409, свой скрытый — 403 `HIDDEN_BY_MODERATOR`.
2. **Сохранение.** `PUT /list-results/:id`:

   ```json
   {
     "revision": 1,
     "title": "Мой топ",
     "description": "",
     "entries": [
       { "itemId": "…", "tierId": "…", "position": 1 },
       { "itemId": "…", "tierId": "…", "position": 2 }
     ]
   }
   ```

   - `itemId` и `tierId` берутся только из `items` и `tiers` этого результата.
   - Чужой id даёт 422 `entries.itemId` или `entries.tierId` с причиной `invalid`.
   - Повтор элемента — `entries.itemId/duplicate`.
   - Ошибка в позициях — `entries.position/invalid`.
3. **Публикация.** `POST /list-results/:id/publish` `{ "revision": 2, "visibility": "public" }`.
   Нужны название и хотя бы один разложенный элемент. Если шаблон скрыт модератором — 403.
4. **Остальные действия** работают так же, как у шаблона:
   `POST …/unpublish`, `PATCH …/visibility`, `POST …/copy` (только свой), `DELETE …` (204).
   Копия результата — черновик с той же раскладкой на том же снимке.

### 3.6 Автосохранение и ревизии

- **Черновик** сохраняйте тем же `PUT` с debounce около 1,5 с после последней правки.
  - Отправляйте не больше одного запроса за раз: следующий — после ответа на предыдущий.
  - В каждый `PUT` передавайте `revision` из последнего успешного ответа.
- **Опубликованный объект** правьте на клиенте и отправляйте `PUT` только по кнопке «Сохранить»:
  любой сохранённый `PUT` сразу виден всем.
  - Предупредите о несохранённых изменениях при уходе со страницы.
- **Когда меняется `revision`.** Её поднимают только `PUT` и обновление элемента из каталога.
  Публикация, снятие и смена видимости её не меняют, но publish принимает `revision`:
  нельзя опубликовать состояние, которого клиент не видел.
- **409 `REVISION_CONFLICT`** значит, что объект изменили в другой вкладке или на другом устройстве.
  Предложите пользователю выбор:
  - «Загрузить актуальную версию» — новый `GET`;
  - «Перезаписать своей» — `GET` за новой `revision`, затем повтор `PUT` с локальными данными.
- **`revision`** — целое число от 1. Без неё `PUT`, publish и refresh дают 422 `revision/required`.

### 3.7 Жалобы

`POST /list-templates/:id/reports` или `POST /list-results/:id/reports`:

```json
{ "reasonCode": "spam" }
```

Ответ 201:

```json
{ "id": "…", "target": "template", "targetId": "…", "reasonCode": "spam", "status": "open", "createdAt": "…" }
```

- Кнопку «Пожаловаться» не показывайте автору: на свой объект ответ 403.
- Жаловаться можно на любой опубликованный объект, который открывается у пользователя, в том числе `unlisted`.
- 409 `ALREADY_REPORTED` значит, что у пользователя уже есть открытая жалоба на этот объект.
  Покажите «Жалоба уже отправлена».
- Не больше 20 жалоб в час на пользователя, иначе 429.
- Жалоба сама ничего не скрывает: решает модератор.

## 4. Обложка и порядок элементов

`coverUrl` считает сервер, клиенту вычислять её не нужно:

| Объект | Обложка |
|---|---|
| шаблон | картинка первого элемента в `items` |
| результат `ranked` | картинка элемента на первом месте |
| результат `tiers` | картинка первого элемента в самом верхнем непустом тире |
| результат `collection` | картинка первого элемента |

`entries` результата приходят в каноническом порядке: по тирам сверху вниз, внутри — по `position`.

## 5. Ошибки

Формат тела:

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "invalid input",
             "details": { "field": "items.title", "reason": "required", "index": 2 } } }
```

`details.index` — номер элемента в массиве из запроса. Он приходит только для ошибок в массивах.
По `field` и `index` можно подсветить конкретное поле.

| HTTP / `code` | Когда |
|---|---|
| 400 `BAD_REQUEST` | тело не JSON, неверный тип поля или неверный UUID в теле |
| 401 `UNAUTHORIZED` | нет входа (для записи и «Моих») |
| 403 `FORBIDDEN` | жалоба на свой объект |
| 403 `HIDDEN_BY_MODERATOR` | публикация, копия или новый результат при скрытом модератором объекте или шаблоне |
| 404 `NOT_FOUND` | нет объекта, он удалён, недоступен или чужой (для записи); неверный UUID в пути |
| 409 `REVISION_CONFLICT` | устаревшая `revision` |
| 409 `ALREADY_REPORTED` | уже есть открытая жалоба |
| 409 `CONFLICT` | недопустимо в текущем состоянии: смена видимости черновика, результат по своему черновику, обновление из каталога своего элемента |
| 413 `PAYLOAD_TOO_LARGE` | тело запроса больше 128 КБ |
| 422 `VALIDATION_ERROR` | см. `details` |
| 422 `QUOTA_EXCEEDED` | лимит: 50 шаблонов или 200 результатов на автора (удалённые не считаются) |
| 429 `RATE_LIMITED` | слишком много жалоб или запросов |

Значения `details.reason`:

| `reason` | Смысл |
|---|---|
| `required` | поле обязательно (в том числе для публикации) |
| `too_long` | превышена длина |
| `too_many` | слишком много элементов или тиров |
| `duplicate` | повтор id или произведения |
| `immutable` | поле нельзя менять (`typeCode`/`format` после публикации, `mediaObjectId`) |
| `invalid` | неверное значение или неизвестный id |
| `type_mismatch` | произведение не того типа, что шаблон |

Частые значения `details.field`:

- `typeCode`, `format`, `title`, `description`, `visibility`, `revision`;
- `tiers`, `tiers.id`, `tiers.name`, `tiers.color`;
- `items`, `items.id`, `items.title`, `items.image`, `items.imageId`, `items.mediaObjectId`;
- `entries`, `entries.itemId`, `entries.tierId`, `entries.position`;
- `reasonCode`, `q`, `type`, `limit`, `cursor`, `status`.

## 6. Кеширование

- **`Cache-Control: no-store`** стоит на ответах автору, «Моих», ответах на команды и admin-ответах.
  Их нельзя кешировать на клиенте между пользователями.
- **Одиночные объекты и профиль** зависят от входа: ответ содержит `Vary: Authorization`.
  После входа или выхода перезапрашивайте страницу.
- **Мутации.** После любой мутации используйте объект из её ответа: это тот же вид, что даёт `GET`
  автору.

## 7. Модерация (для админки)

Все запросы с заголовком `X-Admin-Token`, без него — 401. Пользовательский `Authorization` не подходит.

| Маршрут | Ответ |
|---|---|
| `GET /admin/list-reports?status=open&limit=&cursor=` | открытые жалобы, старые первыми |
| `POST /admin/list-reports/:id/resolve` | 200 с жалобой; уже закрытая — 409 |
| `POST /admin/list-templates/:id/hide`, `/unhide` | 204 |
| `POST /admin/list-results/:id/hide`, `/unhide` | 204 |

Элемент очереди — поля жалобы, а также `reporterId`, `targetTitle`, `targetAuthorId`,
`targetHidden` и `targetDeleted`.

Что происходит при модерации:

- **Скрытие шаблона** скрывает и все результаты по нему.
- **`unhide`** возвращает прежние статус и видимость.
- **Удалённые объекты** тоже можно скрыть: это нужно, чтобы убрать результаты удалённого шаблона.
- **После закрытия жалобы** пользователь может пожаловаться на объект снова.
