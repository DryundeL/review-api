# Топы и подборки (модуль lists)

Здесь описано, как устроены шаблоны (`list-templates`) и результаты (`list-results`).
Шаблон — это набор элементов: произведений из каталога или своих картинок.
Результат — это раскладка элементов шаблона, которую делает пользователь. Он бывает
трёх форматов: тир-лист, топ или подборка.

Все маршруты начинаются с `/v1`. Для записи нужен `Authorization: Bearer …`, гость получает 401.
Чтение работает и без входа, но если вход есть, автор получает свои поля.

## Форматы

| `format` | Что это | Тиры | `entries` результата |
|---|---|---|---|
| `tiers` (по умолчанию) | тир-лист | 1–10, у каждого `name` ≤ 30 и `color` `#RRGGBB` | `tierId` обязателен, `position` — порядок внутри тира |
| `ranked` | топ | нет | `position` — место, начиная с 1 |
| `collection` | подборка | нет | `position` — порядок |

В каждой группе (тир или весь список) позиции идут строго `1..n`, без пропусков и повторов.
Не все элементы обязательно раскладывать: неразложенные просто не попадают в `entries`.

## Объекты в ответах

Шаблон (`GET /list-templates/:id` и ответы команд):

```json
{
  "id": "uuid", "typeCode": "manga", "format": "tiers",
  "title": "Сэйнэн", "description": "", "coverUrl": "https://…",
  "author": { "id": "uuid", "username": "ann", "photoUrl": "…" },
  "firstPublishedAt": "2026-11-26T10:00:00Z",
  "tiers": [{ "id": "uuid", "name": "S", "color": "#ff7f7f" }],
  "items": [{ "id": "uuid", "title": "Berserk", "mediaObjectId": "uuid", "imageUrl": "…" }],
  "canCreateResult": true,

  "revision": 3, "status": "published", "visibility": "public",
  "moderation": "hidden", "createdAt": "…", "updatedAt": "…"
}
```

Поля из последней строки получает только автор. У автора в `items[]` есть ещё `imageId`,
если картинка — его собственная загрузка. Гость никогда не видит `revision`, черновики,
видимость и состояние модерации.

Результат (`GET /list-results/:id`):

```json
{
  "id": "uuid", "typeCode": "manga", "format": "tiers",
  "title": "Мой топ", "description": "", "coverUrl": "…",
  "author": { "id": "uuid", "username": "bob" },
  "firstPublishedAt": "…",
  "template": { "id": "uuid", "title": "Сэйнэн", "author": { "id": "uuid", "username": "ann" } },
  "canCreateOwn": true,
  "tiers": [ … ], "items": [ … ],
  "entries": [{ "itemId": "uuid", "tierId": "uuid", "position": 1 }]
}
```

- `tiers`, `items` и `template.title` берутся из снимка шаблона на момент создания результата.
  Последующие правки шаблона результат не меняют.
- `template.id` приходит, только если шаблон опубликован, публичный, не удалён и не скрыт.
  `canCreateOwn` зависит от того же условия. Только тогда показывайте ссылку на шаблон
  и кнопку «Составить свой» (`POST /list-templates/:templateId/results`).
- `entries` упорядочены канонически: сначала по тирам сверху вниз, затем по `position`.
- Автор получает те же поля, что у шаблона: `revision`, `status`, `visibility`, `moderation`.
  `moderation: "hidden"` у результата бывает и тогда, когда скрыт его шаблон.

Обложка (`coverUrl`) вычисляется на сервере:

- у шаблона — картинка первого элемента;
- в `ranked` — картинка первого места;
- в `tiers` — картинка первого элемента в самом верхнем непустом тире;
- в `collection` — картинка первого элемента.

## Списки

| Маршрут | Что отдаёт |
|---|---|
| `GET /list-templates` | вкладка «Шаблоны»: опубликованные публичные |
| `GET /list-results` | вкладка «Топы пользователей» |
| `GET /profiles/:id/list-templates`, `/list-results` | профиль; закрытый профиль — 404 |
| `GET /profile/list-templates`, `/list-results` | «Мои»: всё, кроме удалённого |

Параметры запроса:

- `q` — до 100 символов, ищется подстрока в названии без учёта регистра;
- `type` — код типа;
- `format`;
- `limit` — 1..50, по умолчанию 20;
- `cursor`.

У «Моих» вместо фильтров есть `status`: `draft`, `published` (публичные), `unlisted`, `hidden` (скрытые модератором).
Пустой `status` — все. Скрытый объект попадает только в `hidden`.

Ответ: `{ "items": [card…], "nextCursor": "…" }`. Если `nextCursor` нет, это последняя страница.
Курсор привязан к вкладке и фильтру статуса. После смены `q`, `type`, `format` или `status`
начинайте с первой страницы.

Карточка содержит `id`, `title`, `typeCode`, `format`, `coverUrl`, `author` и `firstPublishedAt`.
У результата есть ещё `templateTitle`. В «Моих» добавляются `status`, `visibility`, `moderation`
и `updatedAt`.

Раздел и профиль сортируются по дате первой публикации, новые первыми. Снятие с публикации
и повторная публикация эту дату не сбрасывают. «Мои» сортируются по последнему изменению.

## Шаблон: жизненный цикл

1. `POST /list-templates` `{typeCode, format?, title?}` → 201, черновик с `revision: 1`.
   Если `format` не передан, создаётся `tiers` с тирами по умолчанию.
2. `PUT /list-templates/:id` — полная замена:

   ```json
   {
     "revision": 1, "title": "…", "description": "…", "typeCode": "manga", "format": "tiers",
     "tiers": [{ "id": "uuid?", "name": "S", "color": "#ff7f7f" }],
     "items": [{ "id": "uuid?", "mediaObjectId": "uuid?", "title": "…", "imageId": "uuid?" }]
   }
   ```

   - Новый элемент из каталога: без `id`, с `mediaObjectId`. Название и постер сервер берёт
     из каталога. Произведение должно быть того же типа, что шаблон (`type_mismatch`),
     и не повторяться.
   - Свой элемент: `title` и `imageId` из `POST /media/images`.
   - Существующий элемент передаётся со своим `id`. `mediaObjectId` у него менять нельзя
     (`immutable`). Если `imageId` не передан, текущая картинка сохраняется.
   - Тиры и элементы, которых нет в запросе, удаляются. Неизвестный `id` даёт 422.
   - `typeCode` и `format` после первой публикации менять нельзя (`immutable`).
   - Ответ — шаблон с новой `revision`.

   Лимиты: название ≤ 150, описание ≤ 2000, название элемента ≤ 150, до 50 элементов.
3. `POST /list-templates/:id/publish` `{revision, visibility: "public"|"unlisted"}`.
   Для публикации нужны название, хотя бы один элемент, у каждого элемента название
   и картинка, у каждого тира название.
4. `POST …/unpublish` возвращает шаблон в черновик. `PATCH …/visibility` `{visibility}`
   работает только для опубликованного.
5. `POST …/items/:itemId/refresh-from-catalog` `{revision}` заново берёт название и постер
   из каталога. Для своего элемента это 409.
6. `POST …/copy` создаёт новый черновик (201). `DELETE …` — 204. Удалённый шаблон даёт 404 всем,
   но опубликованные результаты по нему остаются.

`unlisted` не попадает в раздел и профиль, но открывается по прямой ссылке.

## Результат: жизненный цикл

1. `POST /list-templates/:templateId/results` → 201, черновик на снимке текущей версии шаблона.
   Работает для любого опубликованного и не скрытого шаблона, который открывается у пользователя,
   в том числе `unlisted`.
2. `PUT /list-results/:id` `{revision, title, description, entries: [{itemId, tierId?, position}]}`.
   Чужой `itemId` или `tierId` даёт 422 `entries.itemId` / `entries.tierId`.
3. `POST …/publish` `{revision, visibility}`. Нужны название и хотя бы один разложенный элемент.
4. `POST …/unpublish`, `PATCH …/visibility`, `POST …/copy`, `DELETE …` работают так же,
   как у шаблона.

## Автосохранение и ревизии

- **Черновик** сохраняйте тем же `PUT` с debounce около 1,5 с после последней правки.
  Новый запрос отправляйте только после ответа на предыдущий. В следующий `PUT` передавайте
  `revision` из последнего ответа.
- **Опубликованный объект** правится на клиенте. `PUT` отправляется только по кнопке
  «Сохранить», иначе незаконченная правка сразу станет видна всем.
- `revision` растёт только при сохранении и при обновлении элемента из каталога.
  Публикация, снятие и смена видимости её не меняют, но принимают её, чтобы не опубликовать
  устаревшее состояние.
- 409 `REVISION_CONFLICT` значит, что объект изменили в другой вкладке. Покажите пользователю
  выбор: перезагрузить объект или перезаписать своими данными. Для перезаписи заново получите
  `revision` через `GET`.

## Жалобы

`POST /list-templates/:id/reports` и `POST /list-results/:id/reports` `{reasonCode}` → 201.
Коды причин берутся из `GET /report-reasons`.

- Жаловаться можно на опубликованный объект, который видит пользователь, в том числе `unlisted`.
- На свой объект — 403.
- Пока у пользователя есть открытая жалоба на этот объект, повторная даёт 409 `ALREADY_REPORTED`.
- Не больше `LISTS_REPORTS_PER_HOUR` жалоб в час на пользователя (по умолчанию 20), иначе 429.
- Жалоба сама ничего не скрывает: решает модератор.

## Модерация (admin, заголовок `X-Admin-Token`)

| Маршрут | Ответ |
|---|---|
| `GET /admin/list-reports?status=open&cursor=&limit=` | открытые жалобы, старые первыми |
| `POST /admin/list-reports/:id/resolve` | 200; уже закрытая — 409 |
| `POST /admin/list-templates/:id/hide`, `/unhide` | 204 |
| `POST /admin/list-results/:id/hide`, `/unhide` | 204 |

- Скрытый шаблон скрывает и все результаты по нему.
- После `unhide` прежние статус и видимость возвращаются сами.
- Автор видит свой скрытый объект с `moderation: "hidden"`, остальные получают 404.

## Коды ошибок

Тело ошибки: `{ "error": { "code", "message", "details"? } }`.

| Код | Когда |
|---|---|
| 400 `BAD_REQUEST` | тело не JSON или неверный UUID в теле |
| 401 `UNAUTHORIZED` | нет входа или admin-токена |
| 403 `FORBIDDEN` | жалоба на свой объект |
| 403 `HIDDEN_BY_MODERATOR` | действие со скрытым модератором объектом (публикация, копия, новый результат) |
| 404 `NOT_FOUND` | объекта нет, он удалён, недоступен или чужой (для записи) |
| 409 `REVISION_CONFLICT` | устаревшая `revision` |
| 409 `ALREADY_REPORTED` | уже есть открытая жалоба |
| 409 `CONFLICT` | действие недопустимо в текущем состоянии: результат по своему черновику, смена видимости черновика, обновление своего элемента из каталога |
| 413 `PAYLOAD_TOO_LARGE` | тело больше 128 КБ |
| 422 `VALIDATION_ERROR` | `details: {field, reason, index?}` |
| 422 `QUOTA_EXCEEDED` | лимит объектов автора: 50 шаблонов (`LISTS_TEMPLATE_QUOTA`) или 200 результатов (`LISTS_RESULT_QUOTA`); удалённые не считаются |
| 429 `RATE_LIMITED` | слишком много жалоб или запросов |

`reason` — стабильный токен: `required`, `too_long`, `too_many`, `duplicate`, `immutable`,
`invalid`, `type_mismatch`. `field` — путь, например `title`, `items.title`, `tiers.color`
или `entries.position`. `index` — номер элемента в массиве из запроса.

## Кеширование

Ответы автору, «Мои», ответы на команды и admin-ответы помечены `Cache-Control: no-store`.
Ответы на чтение отдельных объектов зависят от входа и содержат `Vary: Authorization`.
