# Редактор обзоров: что изменилось и что сделать на фронтенде

Все пути начинаются с `/v1`. Ответы маршрутов редактора приходят с
`Cache-Control: no-store`; клиент тоже не должен их кешировать.

**Изменение несовместимо со старым клиентом.** Сервер и Mini App выкатываются
одновременно. После выкатки сервера старый редактор перестанет сохранять обзоры.

## Коротко: что поменялось

| Было | Стало |
|---|---|
| Обзор состоит из блоков `blocks[]` (до 10, заголовок блока до 50 символов, текст до 500) | Один HTML-текст `body` до 20 000 символов; разделы — заголовки `<h3>` внутри текста |
| Заголовок обзора обязателен | Заголовок необязателен, может быть пустой строкой |
| Оценка обязательна даже в черновике | В черновике оценки может не быть (`rating: null`); обязательна только для публикации |
| Публикация — `status: "published"` в `POST`/`PATCH` | Отдельное действие `POST /reviews/:id/publish` |
| `PATCH /reviews/:id` правит опубликованный обзор сразу | `PATCH` удалён (405). Правки сохраняются в рабочую версию, читатели видят старую до «Обновить публикацию» |
| Черновиков на одно произведение могло быть несколько | Один обзор пользователя на произведение, включая черновик |
| Автор видит свой черновик через `GET /reviews/:id` | `GET /reviews/:id` отдаёт только опубликованное, даже автору. Черновик — через `GET /reviews/draft` |
| — | Конфликт правок с другой вкладки/устройства: 409 `REVISION_CONFLICT` |

## Что сделать на фронтенде

1. Убрать формы блоков и переключатель режимов. Один редактор: название и
   постер произведения, необязательный заголовок, оценка 1–10, поле текста.
2. Панель форматирования: жирный, курсив, списки, цитата, заголовок раздела
   (`<h3>`), «Спойлер». Только теги из списка ниже, без атрибутов.
3. Вход в редактор — через выбор произведения (со страницы произведения оно уже
   выбрано). Сначала `GET /reviews/draft?mediaObjectId=…`; 404 — открыть пустой
   редактор, ничего не создавая.
4. Первое изменение — `POST /reviews`, дальше автосохранение через
   `PUT /reviews/:id/draft` (алгоритм ниже).
5. Статусы сохранения: «Есть несохранённые изменения», «Сохраняется»,
   «Сохранено» (только после ответа сервера), «Не удалось сохранить» + «Повторить».
6. Кнопка «Опубликовать» (черновик) / «Обновить публикацию» (опубликованный
   обзор с правками) → `POST /reviews/:id/publish`. При успехе открыть
   опубликованный обзор.
7. Экран конфликта на 409: показать, что обзор изменён в другом месте, дать
   скопировать свой текст, затем загрузить актуальную версию.
8. Просмотр обзора: рендерить `body` вместо `blocks`; спойлеры `||…||` скрыты до
   нажатия (с клавиатуры тоже).
9. Карточки: если `title` пустой — подпись названием произведения.
10. «Мои обзоры» (`GET /profile/reviews`): различать черновик (`status: "draft"`)
    и опубликованный с правками (`hasUnpublishedChanges: true`); `rating` может
    быть `null`.
11. Ни одна ошибка (сеть, 401, 409, 413, 422, 429) не стирает текст в редакторе.
    Перед уходом с несохранёнными изменениями предупреждать, где позволяет
    Telegram Mini App.

## Маршруты

Все требуют Bearer. Чужой обзор во всех маршрутах редактора — 404.

### `GET /reviews/draft?mediaObjectId=<uuid>`

Свой обзор на произведение (рабочая версия). 200 — объект редактора, 404 — обзора
ещё нет.

### `POST /reviews`

Вызывать при первом изменении в новом редакторе.

```json
{ "mediaObjectId": "uuid", "title": "", "rating": null, "body": "<p>Начал писать</p>" }
```

- 201 — создан черновик.
- 200 — обзор уже был (другая вкладка, повтор запроса). Возвращается он **без
  изменений**: переданный текст не применён. Клиент должен показать пришедшую
  версию либо сразу отправить свой текст через `PUT …/draft` с полученной `revision`.

### `PUT /reviews/:id/draft`

Автосохранение. Поля заменяются целиком: отсутствующий `title` — пустой
заголовок, отсутствующий `rating` — оценка не указана.

```json
{ "title": "Почему стоит посмотреть", "rating": 9, "body": "<h3>Плюсы</h3><p>…</p>", "revision": 3 }
```

`revision` — последняя ревизия, **подтверждённая сервером**. 200 — объект
редактора с новой `revision`. 409 `REVISION_CONFLICT` — обзор изменили в другом
месте, ничего не сохранено. Публичная версия, оценка в статистике, лента и
спойлеры в карточках от автосохранения не меняются.

### `POST /reviews/:id/publish`

```json
{ "revision": 4 }
```

Публикуется ровно эта сохранённая ревизия. Если есть несохранённые правки —
сначала дождаться их сохранения и передать новую `revision`.

- 200 — объект редактора (`status: "published"`, `hasUnpublishedChanges: false`).
- 409 — ревизия не последняя.
- 422 — не хватает текста или оценки (см. ошибки).
- Повтор для уже опубликованной ревизии — 200 без побочных эффектов: второй
  публикации и повторных наград не будет. Кнопку можно безопасно нажать ещё раз.

ID, URL, голоса, просмотры и комментарии при обновлении публикации сохраняются.

### Объект редактора (ответ всех четырёх маршрутов)

```json
{
  "id": "0ec1b87e-cc81-47fa-8787-5d6f5e11a191",
  "mediaObject": { "id": "uuid", "title": "Матрица", "type": "movie", "posterUrl": "https://..." },
  "status": "published",
  "title": "Почему стоит посмотреть",
  "rating": 9,
  "body": "<h3>Плюсы</h3><p>…</p>",
  "revision": 5,
  "hasUnpublishedChanges": true,
  "publishedAt": "2026-11-17T10:00:00.123456Z"
}
```

| Поле | Смысл |
|---|---|
| `status` | `draft` — публичной версии нет (не публиковался или скрыт модерацией); `published` — есть |
| `title`, `rating`, `body` | Рабочая версия. `rating` может быть `null` |
| `revision` | Передавать в следующий `PUT …/draft` и в `publish` |
| `hasUnpublishedChanges` | У опубликованного обзора есть сохранённые неопубликованные правки → кнопка «Обновить публикацию» |
| `publishedAt` | Время последнего обновления публикации; отсутствует, если публикаций не было |

## Алгоритм автосохранения

- Сохранять через ~1 с после последнего изменения (debounce), но не чаще одного
  запроса в 2–3 с: общий лимит API — 60 запросов в минуту с IP.
- Одновременно — не больше одного запроса. Изменения во время запроса копятся и
  уходят следующим запросом с `revision` из ответа текущего.
- Ответ применять, только если после отправки текст не менялся; иначе брать из
  ответа лишь `revision` и сразу планировать следующее сохранение. Запоздалый
  ответ не должен показывать «Сохранено» поверх более нового текста.
- 409 → экран конфликта, автосохранение остановить.
- 401 → текст оставить, после повторного входа повторить сохранение.
- 429 → подождать (учитывать `Retry-After`, если есть) и повторить.
- 413 / 422 → показать ошибку у поля, текст не обрезать.
- Офлайн-хранилище не требуется: после закрытия приложения восстанавливается
  только подтверждённая сервером версия.

## Текст `body`

- Разрешённые теги без атрибутов: `p`, `br`, `b`, `strong`, `i`, `em`, `u`, `s`,
  `ul`, `ol`, `li`, `blockquote`, `pre`, `code`, `span`, `h3`. Любой другой тег,
  атрибут или HTML-комментарий — 422. Очищать вставку из буфера на клиенте
  (сервер всё равно проверит независимо).
- Сервер нормализует HTML и экранирует текст: после сохранения `body` может
  немного отличаться от отправленного — берите версию из ответа при перезагрузке.
- Спойлер — фрагмент между `||` и `||`. Кнопка «Спойлер» оборачивает выделение.
  У перенесённых старых обзоров спойлеры в том же формате.
- Лимит 20 000 символов считается как Unicode code points текста **без тегов**,
  после декодирования сущностей: `&amp;` — 1 символ, emoji — 1 code point
  (некоторые emoji из нескольких code points — больше). Переводы строк и границы
  абзацев (`<p>`, `<br>`) в лимит не входят. Счётчик в редакторе считать так же.
- Для публикации нужен непустой текст: пустые теги, пробелы и `&nbsp;` не считаются.
- Размер JSON-запроса — до 256 КБ, иначе 413.

## Ошибки

422 `VALIDATION_ERROR`, в `details` — `field` и, где есть, `reason`:

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "invalid review", "details": { "field": "body", "reason": "too_long" } } }
```

| `field` | `reason` | Когда |
|---|---|---|
| `body` | `required` | публикация без текста |
| `body` | `too_long` | больше 20 000 символов |
| `body` | `invalid` | запрещённая разметка |
| `rating` | `required` | публикация без оценки |
| `rating` | `invalid` | оценка вне 1–10 |
| `title` | `too_long` | больше 256 символов |
| `title` | `invalid` | содержит `<` или `>` (заголовок — обычный текст) |
| `mediaObjectId` | — | некорректный или несуществующий ID |

Прочее: 400 — некорректный JSON (например, дробная оценка); 401 — нет или
истёк токен; 404 — обзора нет или он чужой; 409 `REVISION_CONFLICT`; 413; 429.

## Публичное чтение

- `GET /reviews/:id`: вместо `blocks` — `body` (только опубликованная версия);
  неопубликованный обзор — 404, в том числе автору.
- Списки, лента, топ обзоров: `body` нет, `hasSpoilers` по опубликованному тексту.
- `title` может быть пустой строкой.
- `GET /profile/reviews` (свой список): рабочие `title` и `rating` (может быть
  `null`), `hasSpoilers` по рабочему тексту, `hasUnpublishedChanges`.

## Перенесённые старые обзоры

Блоки соединены по порядку: заголовок блока стал `<h3>`, тело сохранено как
было. Опубликованные обзоры открываются в редакторе без правок
(`hasUnpublishedChanges: false`). ID, голоса, просмотры и комментарии сохранены.

## Чек-лист проверки

- Новый обзор начинается без заголовка, оценки и текста; открытие редактора
  ничего не создаёт.
- Две вкладки на одно произведение → один обзор; правка во второй вкладке после
  сохранения в первой → экран конфликта, текст можно скопировать.
- Публикация: оценка 1 и 10 проходят, без оценки — ошибка у поля; без заголовка
  проходит; пустой текст — ошибка.
- 20 000 символов сохраняются, 20 001 — ошибка без обрезки (проверить emoji и `&amp;`).
- Правки опубликованного обзора не видны в публичном просмотре до «Обновить публикацию».
- Повторное нажатие «Опубликовать» не создаёт дублей.
- Потеря сети, перезапуск Mini App, истечение сессии — текст не теряется до
  закрытия, после перезапуска восстанавливается последняя подтверждённая версия.
- Мобильный viewport: клавиатура не перекрывает основные действия; спойлеры и
  форматирование доступны с клавиатуры; статусы различимы не только цветом.
