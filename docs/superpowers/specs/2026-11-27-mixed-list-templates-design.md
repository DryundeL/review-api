# Смешанные топы

## Зачем

Нужны топы, не привязанные к одному типу из `review_types`: в одном шаблоне — произведения каталога
разных типов (манга, аниме, фильмы…) вперемешку с ручными элементами (название + своя картинка).
Сейчас у шаблона ровно один обязательный `type_code`, и произведение другого типа даёт 422 `mismatch`.

## Цели и не-цели

- **Цель:** шаблон с типом «смешанный» принимает произведения каталога любого типа и ручные элементы.
- **Цель:** смешанные топы видны в ленте и во вкладках, фильтруются отдельным значением `type=mixed`.
- **Не цель:** фильтр `type=manga` по содержимому смешанных топов. Он ищет только по типу шаблона.
- **Анти-цель:** «смешанный» не должен появиться в справочнике обзоров. Его нельзя выбрать в обзоре,
  в предпочтениях или в геймификации.

## Подходы

- **A (выбран).** В БД `type_code` nullable, NULL = смешанный; в API зарезервированное значение `"mixed"`.
  Справочник обзоров не затронут, поле в API остаётся строкой.
- **B.** Строка `mixed` в `review_types`. Отклонён: справочник общий с обзорами, предпочтениями и поиском,
  пришлось бы исключать её везде.
- **C.** NULL в БД и `typeCode: null` в API. Отклонён: фронту обрабатывать `null`, а фильтру всё равно
  нужно отдельное значение.

## Решения

- **Домен.** `domain.TypeMixed = "mixed"`. Внутри модуля тип по-прежнему строка; только хранилище
  переводит `"mixed"` ↔ NULL. Так домен, команды и HTTP почти не меняются.
- **Миграция `00036`:**
  - `list_templates.type_code` и `list_template_versions.type_code` — `DROP NOT NULL`, FK остаются;
  - `review_types` — CHECK `code <> 'mixed'`, чтобы слово осталось зарезервированным.
- **Создание и сохранение.** `typeCode: "mixed"` не проверяется по справочнику. `checkWorkTypes`
  для смешанного шаблона ничего не проверяет.
- **Смена типа** — только до первой публикации, как сейчас. При переходе из смешанного в конкретный
  тип все произведения каталога проверяются заново (это уже делает `typeChanged`).
- **Чтение.** Везде, где читается `type_code`, — `COALESCE(type_code, 'mixed')`: шаблоны, результаты,
  вкладки, лента.
- **Фильтр `type`.** `type=mixed` → `type_code IS NULL`, любой другой тип — равенство, как сейчас.
  Затрагивает вкладки модуля lists и ленту.
- **Тип элемента.** В JSON элемента шаблона и результата добавляется `mediaType` (omitempty): тип
  произведения каталога, чтобы фронт мог показать бейдж. Ручные элементы его не имеют.
- **Документация.** `frontend-lists.md` и `frontend-feed.md`: значение `mixed`, поле `mediaType`.

## Остаётся на усмотрение исполнителя

- Как именно хранилище маппит `"mixed"` ↔ NULL (`NULLIF($n, 'mixed')` в SQL или в Go перед запросом).
- `mediaType` читается JOIN-ом на `media_objects` по `media_object_id`; если произведение удалено
  из каталога (`ON DELETE SET NULL`), поля нет.

## Тесты

- Домен/команды: создание смешанного, произведения разных типов + ручной элемент, публикация,
  смена смешанного → конкретный с несовпадающим произведением даёт `mismatch`.
- Интеграция: фильтр `type=mixed` во вкладках и в ленте, `type=manga` смешанные не возвращает;
  `INSERT INTO review_types ('mixed', …)` отклоняется.
